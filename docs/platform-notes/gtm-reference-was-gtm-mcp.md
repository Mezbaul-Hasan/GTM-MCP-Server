# Reference review — `mnsmasum62786/was-gtm-mcp` (reviewed 2026-10-30)

Source: https://github.com/mnsmasum62786/was-gtm-mcp — JavaScript (Node ≥ 18), MIT, v3.0.4 (2026-07-28), 9 commits, same author as the GA4 reference (`was-ga4-mcp`). Files: `server.js` (294 lines), `auth.js` (207), `cli.js` (75), `oauth-config.js` (25), `package.json`, `README.md`, `CHANGELOG.md`. Dependencies: `@modelcontextprotocol/sdk ^1.29`, `googleapis ^144`.

## What it is
- 19 "action-style" tools that mirror the whole Tag Manager v2 REST surface: `gtm_account`, `gtm_container`, `gtm_workspace`, `gtm_tag`, `gtm_trigger`, `gtm_variable`, `gtm_built_in_variable`, `gtm_folder`, `gtm_client`, `gtm_zone`, `gtm_template`, `gtm_transformation`, `gtm_gtag_config`, `gtm_version`, `gtm_version_header`, `gtm_environment`, `gtm_destination`, `gtm_user_permission`, `gtm_raw` (call any `tagmanager.v2.*` method by dotted path).
- Each tool takes `action` (`list|get|create|update|delete|revert|…`) + IDs + a free-form `payload` object that is passed straight to the API as the request body. One generic `workspaceResource()` helper serves tags/triggers/variables/clients/zones/templates/transformations/gtag_config.
- Auth = same pattern as the GA4 reference: bring-your-own Desktop OAuth client, loopback redirect `http://127.0.0.1:<port>/callback`, `access_type=offline&prompt=consent`, credentials saved to `~/.was-gtm-mcp/config.json` (0600). Env vars `GOOGLE_CLIENT_ID/SECRET/REFRESH_TOKEN` override the file (multi-account = one `mcpServers` entry per refresh token). CLI `auth | logout | status | help`.
- Scopes requested at `auth` (all at once): `tagmanager.readonly`, `edit.containers`, `edit.containerversions`, `publish`, `delete.containers`, `manage.users`, `manage.accounts`.
- Output: `JSON.stringify(data, null, 2)` truncated at 60,000 chars; errors returned as `isError` text with message/code/status.
- Changelog is almost entirely Windows browser-open fixes (`cmd /c start` → `explorer.exe` → `rundll32 url.dll,FileProtocolHandler`) and a Node 24 ESM path fix — real-world Windows pain points worth remembering.

## Good ideas to take
1. **Coverage map** — the 19 tools are a complete checklist of v2 resources; use it to decide what Phase 1 (read) and Phase 2 (write) must cover and what we deliberately skip (user permissions, account update, destinations link, zones, transformations → not needed for an agency tracking team).
2. **Tag-type hints in the tool description** (`gaawe` GA4 event, `gaawc`/`googtag` Google tag, `html`, `img`, `awct` Ads conversion, `awrmt` Ads remarketing, `sp` Stape, `flc/fls` Floodlight, `ua`, `fb`) — the model needs these to read/create tags.
3. **`revert` as a first-class action** on workspace entities — cheap undo before a version is created.
4. **Version flow** spelled out: `workspaces.create_version` → `versions.publish`; `versions.live` for "what is live now"; `version_headers.latest`; `set_latest`, `undelete` exist.
5. **Multi-account via env vars** (`GOOGLE_REFRESH_TOKEN` per `mcpServers` entry) — compatible with our `GA4_MCP_CONFIG_DIR`/env override idea; keep the same shape for `gtm-mcp`.
6. **Windows gotchas**: open the browser with `rundll32 url.dll,FileProtocolHandler <url>` (not `cmd /c start`); our Python `webbrowser.open()` handles this, but keep the manual-URL fallback printed in the terminal.
7. `gtm_raw`-style escape hatch (we already have `ga4_raw_get`; a **GET-only** `gtm_raw_get` keeps the read-only guarantee).

## Weaknesses we must not copy
1. **Quota is wrong in the README** ("250,000 requests/day, 1,500/100s"). Official limits: **10,000 requests per project per day and 0.25 QPS per project (25 requests per 100-second sliding window)**, daily reset midnight PST (https://developers.google.com/tag-platform/tag-manager/api/v2/limits-quotas). No throttling, caching or batching in the code → an agent that lists tags+triggers+variables for a few containers hits 429 quickly. We need a client-side rate limiter (token bucket 0.25 rps, burst ≤ 25), `Retry-After`/exponential backoff, and "fetch a workspace once, answer many questions from it" helpers.
2. **No pagination** — `tags.list`, `triggers.list`, `variables.list`, `versions.list` etc. return `nextPageToken`; the reference ignores it (large containers silently truncated at the first page) and then truncates the JSON at 60 KB.
3. **All write scopes requested up front** (incl. `delete.containers`, `manage.users`, `manage.accounts`) and no tool annotations/confirmation tiers — `publish`, `delete` and `combine` containers sit next to `list` in the same tool. Violates our §5/§6 rules (read-only default profile, 🟡/🔴 annotations, `dry_run`).
4. **Raw `payload` passthrough** — the model must know the exact GTM JSON schema for a tag (e.g. `parameter: [{type:"template", key:"eventName", value:"purchase"}]`); no validation, no preview/diff, so a typo creates a broken tag. We want typed helpers for the common cases (GA4 event tag, Google tag config, custom-event trigger, data-layer variable) plus a generic path for the rest.
5. **No tests, raw JSON output, secrets in `claude_desktop_config.json`** (multi-account instructions paste client secret + refresh tokens into the config file) — against our "never paste secrets" rule; we point multi-account users to `GTM_MCP_CONFIG_DIR` instead.
6. `googleapis` discovery client is heavy and Node-only; we use `httpx` against `https://tagmanager.googleapis.com/tagmanager/v2/…` through `common/http.py` like ga4-mcp.

## Implications for our `servers/gtm-mcp` design
- **Phase 1 🟢 read**: `gtm_list_accounts`, `gtm_list_containers`, `gtm_get_container`, `gtm_list_workspaces`, `gtm_get_workspace_status`, `gtm_list_tags`, `gtm_get_tag`, `gtm_list_triggers`, `gtm_get_trigger`, `gtm_list_variables`, `gtm_get_variable`, `gtm_list_built_in_variables`, `gtm_list_folders`, `gtm_list_templates`, `gtm_list_versions`, `gtm_get_live_version`, `gtm_get_version`, `gtm_list_environments`, `gtm_raw_get`; helpers `gtm_find_container` (by GTM-XXXX public id), `gtm_container_audit` (paused tags, UA tags, duplicate GA4 measurement IDs, tags without triggers, dangling references, unused variables/triggers, placeholder IDs), `gtm_check_ga4_ecommerce_coverage` (which of the 11 ecommerce events have a GA4 event tag + custom-event trigger).
- **Phase 2 🟡 write (workspace only, `dry_run=True` default, preview first)**: `gtm_create_workspace`, `gtm_create_tag` / `gtm_update_tag`, `gtm_create_trigger`, `gtm_create_variable`, `gtm_enable_built_in_variables`, `gtm_revert_entity`, `gtm_create_version`; recipe `gtm_plan_ga4_ecommerce_setup` → `gtm_apply_plan`. **🔴**: `gtm_publish_version` (and nothing else destructive — no container/account delete, no user management).
- **Scopes**: default `tagmanager.readonly`; `auth --with-writes` adds `tagmanager.edit.containers` + `tagmanager.edit.containerversions` + `tagmanager.publish`. Never `delete.containers`, `manage.users`, `manage.accounts`.
- **Quota handling** in `common/http.py`: per-process token bucket (0.25 rps, burst 25) + backoff on 429/`RESOURCE_EXHAUSTED`; audit/coverage helpers fetch each list once per call and paginate fully.
- **IDs**: accept `GTM-XXXXXX` public id and resolve to `accounts/{a}/containers/{c}` via `accounts.list` → `containers.list` (cached for the process lifetime); accept raw numeric ids too.
